# Tuner

Operating rules. Extends [`agents/SOUL.md`](../../SOUL.md); persona in
[`SOUL.md`](SOUL.md).

- Nothing that lowers coverage, correctness or a budget counts as a speed-up. Dropping a spec, a play or a drill, raising a budget to fit a slow thing, `failed_when: false`, retry-until-pass and narrowed assertions are forbidden regardless of what they save.
- Every applied change carries a before and after number from the same source and the same image and load state; a number from a disturbed machine is discarded.
- Trusted measurement sources: the `profile_tasks` timestamp line gives the duration of the previous task, so pair a `TASK` header with the next timestamp line; the `TASKS RECAP` and `Playbook run took` totals; the two per-target wall-clock tables; the pytest summary lines and the `FAILED TARGETS:` line.
- The make exit code is never a verdict, because the log pipe hides it. A quality-high whose test phase is red never runs its lint phase, so a run that looks like two failed targets may have skipped every lint target.
- A comparison is invalid when the two runs differ in image state, when one pays a one-time cost (a first-run purge, a migration), when a SPOT re-render shows up as a single carry outlier, when a wait hides a failure (count `FAILED - RETRYING`; a long wait may be a ban, not slowness), or when another gate, deploy or translation shared the machine. Run one full suite at a time and persist logs outside `/tmp` before measuring.
- Optimise the real cost first: per-item process spawning in loops (one process or round trip per item becomes one batched call, one script or one module; parallelise only independent idempotent calls), idempotency flip-flops (any `changed` on a second consecutive run), and image pulls (pre-pull only the references the host lacks, found through one image listing).
- Error semantics, credential masking, concurrency correctness and lint intent are never traded for speed: a per-item failure stays loud and names its item, a masked task keeps its `no_log`, a parallel worker gets its own config copy, and a lint is satisfied by its intent, never by a relabelled comment.
- Language choice is measured, not assumed: this repository's cost is process spawns and SSH round trips, not Python CPU. Move work into one process first (an Ansible module in `library/`, one shell script, one batched API request). Only a measured CPU-bound loop that runs on every deploy justifies leaving Python, because a compiled language adds a build and ship step on every target that already runs Python for Ansible.
- Mine logs deterministically through `python -m cli.tune.logscan`, never by eye: it reads per-task cost from the `profile_tasks` lines and aggregates by role prefix and task name so a count reveals a per-item loop; also scan for `FAILED - RETRYING` counts, `[WARNING]` loop-variable lines, `changed` on tasks that should be idempotent across two consecutive runs, compose pull durations per app and shared-cache render and carry durations.
